# Скрипты физического AiNex

Для ходьбы по линии нужен **один файл — `line_follow.py`**. Скопируйте его в `/home/ubuntu/robotrio/` внутри ROS Noetic-контейнера `ainex`. Штатные драйверы HiWonder, MotionManager, камера и ActionGroups должны быть установлены на роботе.

[Инструкция по загрузке и запуску](LINE_TEST_RU.md).

```bash
source /opt/ros/noetic/setup.bash
source /home/ubuntu/ros_ws/devel/setup.bash
cd /home/ubuntu/robotrio

# Наблюдение без движения
python3 line_follow.py --max-seconds 30
```

Движения вызываются через штатный `MotionManager.run_action`. Используются пять испытанных вами ActionGroups; диапазоны сервоприводов дополнительно не проверяются. Первый запуск можно ограничить одним действием:

```bash
python3 line_follow.py --execute --empty-hands \
  --image-orientation standard --max-actions 1 --max-seconds 30
```

`standard` используйте только после проверки ориентации; для зеркального изображения нужен `mirrored`. Голова остаётся в текущем положении. Скрипт экспериментальный, на реальном роботе ещё не проверен.

`tag_grab.py` — отдельный проверенный сценарий захвата двух кубов. Его параметры, порядок захвата и размещения не изменены. Корневые `line_follow.py` и `tag_grab.py` — ссылки на исходники этой папки.

## Размещение куба одной рукой

`ActionGroups/place_block_left.d6a` и `ActionGroups/place_block_right.d6a` —
отдельные SQLite ActionGroups для левой и правой руки. Исходный `place_block`
и вызовы в `tag_grab.py` не изменены. Штатные `left_hand_put_block` и
`right_hand_put_block` используют другие положения и 10 кадров без приседания,
поэтому не заменяют разделение этой 24-кадровой последовательности.

В каждой новой группе сохранены все 24 кадра, их индексы, порядок и длительности
(всего 10,52 с). Значения ног/корпуса (ID 1–12) и выбранной руки взяты без
изменений из исходника. Кадры 1–2 задают начальную позу и приседание,
3–12 содержат траекторию правой руки (открытие ID 22 в кадре 5), 13–22 —
левой (открытие ID 21 в кадре 15), 23–24 — подъём. Кадры другой руки
сохранены по времени; её пять сервоприводов зафиксированы в позе кадра 1:

| Группа | Выбранная рука | Фиксированная противоположная рука (ID: значение) |
| --- | --- | --- |
| `place_block_left` | 13, 15, 17, 19, 21 | 14: 165, 16: 170, 18: 520, 20: 930, 22: 570 |
| `place_block_right` | 14, 16, 18, 20, 22 | 13: 835, 15: 830, 17: 480, 19: 70, 21: 430 |

Это абсолютные команды исходной позы, а не пропуск команд противоположной
руке: `MotionManager` назначает ID по позиции столбца и отправляет все 22
значения. `NULL`, нули и удаление промежуточных столбцов не используются.
В исходнике и новых группах нет столбцов ID 23–24: команды голове не отправляются.
Группы рассчитаны на удержание противоположной рукой именно в указанной
исходной позе. Если её текущая поза отличается, первый кадр переместит её;
сохранение произвольного захвата не гарантируется. В частности,
`clamp_left` заканчивается значением ID 21 = 400, а здесь фиксируется 430.
Поэтому результат существующего захвата нельзя считать автоматически
совместимым без отдельной проверки удержания.

После левой группы ID 21 = 500, ID 22 = 570; после правой — ID 21 = 430,
ID 22 = 500. Последовательный вызов двух групп снова задаёт исходную позу
противоположной руке и может закрыть уже открытый захват. Эти файлы не
обеспечивают динамическое удержание текущей позы при последовательных вызовах.

Для установки скопируйте только эти два файла в штатную папку
`/home/ubuntu/software/ainex_controller/ActionGroups/`. Имена для существующего
`MotionManager.run_action`: `place_block_left` и `place_block_right` (без
расширения). Для отдельной папки укажите её в `MotionManager(action_path=...)`.
Логика автоматического выбора руки и сценарий захвата здесь не меняются.
