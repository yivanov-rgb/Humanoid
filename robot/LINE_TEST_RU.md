# Ходьба по линии на реальном AiNex

Нужен **один файл — `line_follow.py`**. Он читает камеру, находит линию и выбирает штатное движение: шаг вперёд, приставной шаг влево/вправо или поворот. Другие пользовательские Python-файлы для запуска не нужны. Используются уже установленные на роботе ROS, MotionManager и ActionGroups.

Пять штатных движений испытаны вами на роботе. Скрипт вызывает их через `MotionManager.run_action`; дополнительной проверки диапазонов сервоприводов и настройки пределов нет.

Без `--execute` скрипт только показывает решения. Положение головы он не меняет. `tag_grab.py` и его калибровка сохранены.

## 1. Скопировать файл

На ноутбуке из корня проекта:

```bash
read -r -p 'SSH-адрес робота user@IP: ' ROBOT_SSH
scp robot/line_follow.py "$ROBOT_SSH":/tmp/line_follow.py
ssh "$ROBOT_SSH"
```

На хосте робота, при работающем контейнере `ainex`:

```bash
docker exec ainex mkdir -p /home/ubuntu/robotrio
docker exec ainex bash -c 'if [ -f /home/ubuntu/robotrio/line_follow.py ]; then cp -p /home/ubuntu/robotrio/line_follow.py /home/ubuntu/robotrio/line_follow.py.backup; fi'
docker cp /tmp/line_follow.py ainex:/home/ubuntu/robotrio/line_follow.py
docker exec -it ainex bash
```

Настройки из `simulation/` копировать не нужно. Используются штатные `.d6a` робота: `forward_one_step`, `move_left`, `move_right`, `turn_left`, `turn_right`.

## 2. Подготовить окружение

Далее все команды выполняются **внутри `ainex`**:

```bash
source /opt/ros/noetic/setup.bash
source /home/ubuntu/ros_ws/devel/setup.bash
cd /home/ubuntu/robotrio
python3 -m py_compile line_follow.py
python3 line_follow.py --help
```

Драйверы и камера должны быть запущены штатным способом. Остановите другие сценарии движения. Проверьте изображение камеры: линия резкая и контрастная, корпус не закрывает рабочую область. Поза головы остаётся текущей.

## 3. Проверить распознавание без движения

```bash
python3 -u line_follow.py --max-seconds 30
```

Если камера публикует другой топик, укажите его:

```bash
python3 -u line_follow.py --image-topic /ваш/топик --max-seconds 30
```

Поиск идёт вплотную к нижнему краю: три соседние полосы от 80% до 100% высоты. Для изображения 640×480 это Y=384–479, общая высота 96 пикселей вместо прежних 120; по X сохраняется центральная половина кадра (160–480). Ближняя полоса задаёт боковое смещение, разность между дальней и ближней — направление линии. Положение головы не меняется. Границы задаются константой `ROIS` в начале скрипта.

В журнале видны смещение `offset`, наклон `heading` и выбранное действие. Зелёные прямоугольники показывают актуальные области поиска. В графической сессии можно открыть размеченное изображение:

```bash
rosrun rqt_image_view rqt_image_view /line_follow/image
```

На неподвижном роботе сместите линию физически вправо. Если `offset` положительный, ориентация — `standard`; если отрицательный — `mirrored`. Проверьте выбранную ориентацию, например:

```bash
python3 -u line_follow.py --image-orientation standard --max-seconds 30
```

Ожидаемые решения: линия по центру → `forward_one_step`, параллельно справа → `move_right`, слева → `move_left`; при наклоне — соответствующий поворот. Для надёжного решения линия должна быть видна минимум в двух рабочих областях. При потере линии движение не начинается.

## 4. Запустить движение

Сначала установите робота в устойчивую штатную стойку на полу, освободите руки и зону движения. Проверьте решения в наблюдении. В примерах ниже `standard` замените на фактически проверенную ориентацию.

Первый запуск — максимум одна ActionGroup:

```bash
python3 -u line_follow.py \
  --execute --empty-hands --image-orientation standard \
  --max-actions 1 --max-seconds 30
```

Оцените направление шага, равновесие и положение линии после движения. Затем можно ограничить серию:

```bash
python3 -u line_follow.py \
  --execute --empty-hands --image-orientation standard \
  --max-actions 10 --max-seconds 60
```

Непрерывное следование до остановки оператором:

```bash
python3 -u line_follow.py \
  --execute --empty-hands --image-orientation standard
```

**Остановка — Ctrl+C.** Уже отправленный кадр может завершиться; оператор должен иметь возможность поддержать и остановить робота. Скрипт не устанавливает начальную стойку автоматически и не измеряет физическую успешность шага.

## Основные параметры

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `--image-topic` | `/camera/image_raw` | Топик `sensor_msgs/Image` |
| `--line-color` | `black` | `black` или `white` |
| `--threshold` | `80` | Порог яркости 0–255 |
| `--deadband` | `0.04` | Допустимое боковое смещение относительно ширины кадра |
| `--heading-deadband` | `15` | Допустимый наклон линии, градусы |
| `--max-actions` | `0` | Максимум ActionGroups; 0 — без ограничения |
| `--max-seconds` | `0` | Максимальное время; 0 — без ограничения |
| `--action-path` | Штатный каталог AiNex | Другой каталог `.d6a`, если нужен |

Настраивайте по одному параметру в режиме наблюдения. Алгоритм ещё не подтверждён на реальном роботе; последнее симуляционное испытание кривой линии выявило чрезмерный боковой уход. Полное прохождение кривой проверяется после единичных движений на прямой.
