# Ручная отладка AiNex в Gazebo

Все команды выполняются на локальном компьютере из папки `Humanoid`. Управление идёт в контейнер `humanoid-ainex-sim`, изолированный от сети физического робота.

Девять реальных действий подготовлены в `simulation/actiongroups` и проверены на креплении. Для скрипта линии — [отдельная инструкция](LINE_FOLLOW_RU.md), для итогов — [результаты испытаний](TEST_RESULTS_RU.md), для всех исходных файлов — [инвентаризация](ACTION_GROUPS_RU.md).

## 1. Подготовить ActionGroups и образ

Файлы `.d6a` должны лежать непосредственно в выбранной папке. Стандартный каталог стенда:

```text
Humanoid/simulation/actiongroups/
```

Можно скопировать файлы туда или подключить существующий каталог без копирования. Например, после выгрузки с робота из предыдущей инструкции:

```bash
cd /home/yor/projects/Humanoid
export ROBOTRIO_ACTIONS_DIR="$PWD/simulation/artifacts/d6a_from_robot/home/ubuntu/software/ainex_controller/ActionGroups"
```

Для подготовленного набора из девяти файлов в `simulation/actiongroups` переменная не нужна. Пример выше подключает весь исходный каталог, в котором есть действия, не совместимые с нынешними ограничениями URDF. `.d6a` подключаются только для чтения и не встраиваются в образ. Чтобы сменить каталог, остановить и заново запустить контейнер.

После обновления кода стенда один раз пересобрать образ:

```bash
bash simulation/sim.sh build
```

## 2. Запустить окно Gazebo

Из терминала активного локального графического сеанса:

```bash
bash simulation/sim.sh gui
```

Эквивалент:

```bash
bash simulation/sim.sh up --gui
```

Каталог действий можно передать прямо при запуске:

```bash
bash simulation/sim.sh gui --actions-dir /absolute/path/to/ActionGroups
```

На Linux поддерживаются X11 и XWayland в Wayland-сеансе. Скрипт использует `DISPLAY`, `XAUTHORITY` и Unix-сокет дисплея. Ключ авторизации копируется в приватный файл; `xhost +`, privileged-режим, устройства робота и host network не используются.

Для диагностики доступа к дисплею на хосте нужны `xauth`, `xdpyinfo`, `timeout`. Если их нет, установить через пакетный менеджер своей системы; в Ubuntu это `xauth`, `x11-utils`, `coreutils`. Обычный SSH-сеанс без локального графического дисплея для команды `gui` не подходит. Режим `DISPLAY=localhost:10.0` через SSH X-forwarding этим скриптом не поддерживается.

Если контейнер уже запущен, сначала остановить его:

```bash
bash simulation/sim.sh stop
bash simulation/sim.sh gui
```

Терминал запуска можно закрыть: контейнер работает в фоне. Журнал:

```bash
bash simulation/sim.sh logs
```

## 3. Выбрать режим модели

По умолчанию корпус свободен. Явный `gui --anchored` закрепляет корпус в пространстве на высоте 0.40 м. Этот режим удобен для проверки рук, головы и последовательности суставов: робот не падает, но шаги и повороты корпуса не перемещают модель по сцене.

Для эксперимента со свободной динамикой:

```bash
bash simulation/sim.sh stop
bash simulation/sim.sh gui --free
```

Или:

```bash
ROBOTRIO_ANCHORED=false bash simulation/sim.sh gui
```

В свободном режиме робот может потерять равновесие до или во время действия. Последовательности `.d6a` воспроизводятся как суставные команды; устойчивость, трение, скорость и угол перемещения требуют отдельной настройки модели. Восемь `turn_right` не считаются заранее подтверждённым поворотом на 90°, а двенадцать `forward` — заданным расстоянием.

В ранней проверке без начальной стойки модель упала до действия. Теперь свободный запуск готовит stand; перед тестами проверить `initial_pose_ready: true` через `bash simulation/sim.sh status`. Для проверки зрения без перемещения можно явно включить `--anchored`; свободная ходьба пока не подтверждена.

Для возврата к исходной сцене остановить и заново запустить контейнер. Перезапуск также сбрасывает позы кубов и состояние проигрывателя. Перед любым Reset в Gazebo выполнить `stop-action`. Сброс времени назад автоматически прекращает активное действие; Reset World/Model Poses может менять только позы без сброса времени и не заменяет явную остановку.

## 4. Просмотреть доступные действия

В другом терминале на хосте:

```bash
bash simulation/sim.sh list-actions
bash simulation/sim.sh action-info stand
```

`action-info` проверяет SQLite-файл и показывает количество кадров, длительность, число сервоприводов и хеш. Команды из следующих разделов применимы при наличии соответствующих файлов в выдаче `list-actions`. Имя можно передавать без расширения `.d6a`.

Пустой список означает, что подключённый каталог пуст либо файлы находятся в другом вложенном каталоге. Подключать следует саму папку `ActionGroups`, а не корень распакованного архива.

## 5. Запускать отдельные движения

Команда завершается после полного воспроизведения либо возвращает ошибку. На старте GUI никаких ActionGroups автоматически не исполняется.

| Назначение | Команда на хосте |
|---|---|
| Поза стоя | `bash simulation/sim.sh action stand` |
| Подготовка к ходьбе | `bash simulation/sim.sh action walk_ready` |
| Один шаг вперёд | `bash simulation/sim.sh action forward_one_step` |
| Шаг назад | `bash simulation/sim.sh action back_step` |
| Перемещение влево | `bash simulation/sim.sh action move_left` |
| Перемещение вправо | `bash simulation/sim.sh action move_right` |
| Один фрагмент поворота направо | `bash simulation/sim.sh action turn_right` |
| Один фрагмент движения вперёд | `bash simulation/sim.sh action forward` |
| Анимация захвата левой рукой | `bash simulation/sim.sh action clamp_left` |
| Анимация захвата правой рукой | `bash simulation/sim.sh action clamp_right` |
| Анимация размещения | `bash simulation/sim.sh action place_block` |

Для незнакомого действия сначала выполнить `action-info` и посмотреть его в режиме с креплением. Проигрыватель перед началом проверяет весь файл: длительности, значения pulse, соответствие ID суставам и ограничения URDF. Неподходящие команды завершаются ошибкой; значения автоматически не подрезаются.

`.d6a` может содержать команды всем 24 сервоприводам. Поэтому отдельный `clamp_right` может менять также левую руку, ноги и голову. Удержание занятой руки из `tag_grab.py` не включается автоматически в ручном проигрывателе. Последовательность ручных вызовов не является проверенным сценарием переноски двух кубов; наличие куба в руке отдельно не подтверждается.

## 6. Повторы и последовательности

Три фрагмента движения вперёд:

```bash
bash simulation/sim.sh action forward --repeat 3
```

Восемь поворотов с паузой 0.1 секунды между повторениями:

```bash
bash simulation/sim.sh action turn_right --repeat 8 --pause 0.1
```

Демонстрация поворота, движения и размещения:

```bash
bash simulation/sim.sh action turn_right --repeat 8 --pause 0.1 &&
bash simulation/sim.sh action forward --repeat 12 &&
bash simulation/sim.sh action place_block
```

`&&` запускает следующий этап только при успешном программном завершении предыдущего. Эта последовательность показывает движения и не проверяет захват/сохранность предметов. Проверенный сценарий захвата двух ID в `tag_grab.py` остаётся отдельным компонентом.

Одновременно работает один проигрыватель. Второй запуск движения во время первого отклоняется. Длительность кадров учитывается по времени симуляции; при паузе или остановке `/clock` проигрывание прекращается по watchdog. Перед запуском действия снять Pause в GUI.

## 7. Остановить действие или весь стенд

Из второго терминала:

```bash
bash simulation/sim.sh stop-action
```

Это прекращает воспроизведение и интерполяцию, оставляя суставные цели в текущем положении. Физика свободной модели продолжает работать; остановка действий не закрепляет падающего робота. Для остановки физики использовать кнопку Pause в Gazebo.

Полностью закрыть GUI и контейнер:

```bash
bash simulation/sim.sh stop
```

При штатном `stop` также удаляется приватная копия Xauth-ключа. Исходный ключ графического сеанса не изменяется. Простое закрытие окна Gazebo не заменяет остановку контейнера.

## 8. Смотреть суставы и камеру

Подключиться к контейнеру:

```bash
bash simulation/sim.sh shell
```

Внутри:

```bash
rostopic echo -n 1 /joint_states
rosservice call /controller_manager/list_controllers "{}"
rosrun rqt_image_view rqt_image_view
```

В окне изображения выбрать `/camera/image_raw`. Окно Gazebo и `rqt_image_view` используют один графический сеанс. При ручном вводе команд суставам помнить: во время ActionGroup цели публикует адаптер; прямые команды тем же контроллерам будут с ним конфликтовать.

Исходная камера модели закреплена на корпусе; её наклон 0.45 рад в этом стенде — условная настройка сцены. Движение `head_pan/head_tilt` пока не означает соответствующего изменения картинки. Пороговые пиксели захвата реального робота в симулятор автоматически не переносятся.

## 9. Использовать калибровку своего экземпляра

По умолчанию ID, начальные pulse и знаки берутся из официального `servo_controller.yaml`. Если рабочая конфигурация робота отличается, подключить её при запуске:

```bash
bash simulation/sim.sh stop
ROBOTRIO_SERVO_CONFIG=/absolute/path/to/servo_controller.yaml \
  bash simulation/sim.sh gui --actions-dir /absolute/path/to/ActionGroups
```

Файл подключается только для чтения. Преобразование соответствует Hiwonder:

```text
angle = (pulse − init) / coefficient
coefficient = ±(180 / 3.1415926 / 240 × 1000)
```

Знак определяется порядком `min`/`max` в конфигурации. Если корректная для робота ActionGroup выходит за ограничения модели, сравнить калибровку и URDF до изменения параметров. Рабочие значения на физическом роботе ради прохождения симуляции не менять.

## 10. Минимальная проверка после изменений

```bash
bash simulation/sim.sh test
bash simulation/sim.sh test-container
bash simulation/sim.sh smoke
```

Затем в GUI проверить конкретное движение, записать наблюдение и критерий успеха. Прежний `action_replay.json` относится к синтетическим данным. Теперь отдельно проверены девять реальных действий и скрипт линии на настоящей камере Gazebo: 11 проверок в `artifacts/line_follow_integration.json`. Это проверка на креплении; свободная ходьба, физический захват и маршрут А→Б не подтверждены.

При добавлении GUI и проигрывателя прошли 23 регрессионных теста, базовый smoke и 8 интеграционных проверок воспроизведения. Результат последнего теста — `simulation/artifacts/action_replay.json`.
