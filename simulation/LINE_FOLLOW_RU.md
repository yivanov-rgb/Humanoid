# Ходьба по линии в Gazebo

На реальном роботе используется один самостоятельный [robot/line_follow.py](../robot/line_follow.py). [Команды для робота](../robot/LINE_TEST_RU.md). Симуляционные сервисы и положение виртуальной головы вынесены в `robotrio_sim/line_backend.py`; копировать этот адаптер на робота не требуется.

Сцена по умолчанию не содержит кубов. Чёрная линия шириной 30 мм — дуга длиной 2 м и радиусом 6 м, с общим поворотом 19,1°. Пол ровный, линия не имеет коллизии. Последний GUI-прогон прежней версии остановлен при удалении от линии на 8 см; успешное прохождение дуги пока не подтверждено.

## Запустить ограниченный тест с GUI

Из корня проекта на компьютере:

```bash
bash -eu <<'BASH'
trap 'bash simulation/sim.sh stop' EXIT
trap 'exit 130' INT
trap 'exit 143' TERM
bash simulation/sim.sh test-container
bash simulation/sim.sh gui --free
docker exec humanoid-ainex-sim /opt/ainex-entrypoint.sh timeout 80s \
  python /workspace/tests/check_initial_pose.py
docker exec humanoid-ainex-sim /opt/ainex-entrypoint.sh timeout 140s \
  python /workspace/tests/check_line_free.py --max-actions 30 --max-seconds 110 --view
BASH
```

Модель создаётся в позе `stand`, затем проверяются положение на полу, опущенные руки и устойчивость. Ходьба разрешается после `initial_pose_ready: true`; независимый тест дополнительно наблюдает стойку минимум 5 секунд симуляции. Крепления к `world` нет. При неуспешной подготовке следующие команды не выполняются.

Адаптер симуляции перед первым действием задаёт виртуальную голову 500/300 и проверяет обратную связь. Это настройка стенда: аппаратный `line_follow.py` голову не двигает. Все движения берутся из перенесённых `.d6a`; адаптер обращается к существующему симуляционному серверу действий.

Тест измеряет расстояние до дуги, а не отклонение от постоянной мировой Y. Допуск центрирования — 5 см. При удалении более 8 см, наклоне более 25° или снижении корпуса более 4 см тест прекращается и физика ставится на паузу. Отчёт: `artifacts/line_free_probe.json`; журнал: `artifacts/line_free.log`; кадры: `artifacts/line_free_{raw,debug}.png`. Ограниченная серия не подтверждает всю двухметровую дугу.

## Ручное наблюдение и движение

Запустите стенд и дождитесь подтверждения стойки:

```bash
bash simulation/sim.sh gui --free
bash simulation/sim.sh status
```

Во втором терминале можно открыть изображение и запустить скрипт:

```bash
bash simulation/sim.sh line-view
# В отдельном терминале, без движения:
bash simulation/sim.sh line --image-orientation standard --max-seconds 30
# После проверки кадра: не более трёх действий, руки пустые:
bash simulation/sim.sh line --execute --empty-hands --image-orientation standard --max-actions 3
```

Наблюдение сохраняет текущую голову. На свежем стенде камера ещё может требовать подготовки; первым двигателем её готовит только симуляционный адаптер. Для проверки интерфейсов без ходьбы используйте отдельно обозначенные диагностические сценарии, а не подвес вместо свободного теста.

Скрипт различает смещение и наклон: параллельная линия сбоку вызывает `move_left`/`move_right`, большой наклон — `turn_left`/`turn_right`, центр — `forward_one_step`. Для решения нужны минимум две ROI и несколько новых согласованных кадров. После действия кадры движения отбрасываются. При потере линии/камеры слепого поиска нет.

Оставляйте только один источник движения. Для остановки:

```bash
bash simulation/sim.sh line-stop
bash simulation/sim.sh stop
```

`line-stop` запрещает новые команды. `stop` закрывает Gazebo GUI, ROS-процессы и контейнер стенда; после каждого опыта он обязателен. После закрытия просмотрщика также завершите запущенную им команду, если она ещё работает.

AprilTag и размещение объектов не входят в упрощённый скрипт линии. Проверенный `tag_grab.py` сохранён отдельно. Упрощение структуры само по себе не исправляет ранее обнаруженный боковой уход — это отдельная задача отладки. Исторические измерения и ограничения: [TEST_RESULTS_RU.md](TEST_RESULTS_RU.md).
